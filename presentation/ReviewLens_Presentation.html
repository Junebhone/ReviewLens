[~60 s · 0:00–1:00]
Hello everyone, I'm Quoc, and our project is ReviewLens. Every online seller has the same problem: thousands of reviews come in, and the ones that matter most, from unhappy customers, are buried in the pile. Our goal is to sort every review automatically into Negative, Neutral or Positive.
What makes this project interesting is that we solve the same task in three different ways, on exactly the same data. Longqi fine-tunes BERT, Bhone fine-tunes Llama with QLoRA, and I take the opposite route: the same Llama with no training at all, only prompting. So we can ask a practical question: how much does training actually buy you?
We judge everything by macro-F1, so the hard Neutral class counts as much as the easy ones. And keep this review in mind: it has three stars, but it reads like a complaint. We'll come back to that.

[~60 s · 1:00–2:00]
All three methods share one dataset, so any difference in results comes from the method, not the data. We start from Amazon's Cell Phones and Accessories reviews, keep reviews long enough to carry a real opinion, and clean out the noise.
Labels come from the star rating, which is standard practice, but it creates a problem: Neutral reviews are by far the rarest. On the natural mix, a model could almost ignore Neutral and still look good. So we draw a balanced sample and fix one train, validation and test split that everyone uses.
There's one assumption here worth questioning: is the star rating really the truth? To test it, I added Experiment 2: a separate set of reviews labelled by Claude from the text alone, with the stars hidden. Scoring every method against both label sets lets us separate model error from label noise.

[~40 s · 2:00–2:40]
My method needs no training at all. Llama 3.1 8B Instruct reads one prompt: instructions, a short definition of each label, a few labelled examples, and then the review. It answers with greedy decoding, so every result is deterministic and reproducible, and a simple parser extracts the label.
The real design work is the prompt itself. I treated it like a hyperparameter: I compared eight designs on the validation set only and kept the test set untouched until the end. One trade-off to keep in mind is cost: the winning prompt is about ten times longer than zero-shot, so every prediction is slower and more expensive.

[~45 s · 2:40–3:25]
That design work pays off: a well-chosen prompt adds about ten points of macro-F1, with zero training. What matters is where the gain comes from. Negative and Positive were already easy; almost all of the improvement is on Neutral. The examples show the model what a “middle” review looks like, which an instruction alone doesn't convey.
But the confusion matrix shows Neutral is still the weak point, and the error goes in one direction: Neutral reviews get pushed toward Negative, and rarely toward Positive. When I read those reviews, many are real complaints from customers who still gave three stars. So the question becomes: is the model wrong, or is the label?

[~40 s · 3:25–4:05]
Before I answer that, a quick look at how I chose the prompt. Two lessons stand out. First, examples matter more than instructions: definitions help, but examples help more. Second, more isn't always better: going beyond five examples per class actually hurts, and which examples you pick matters almost as much as how many. That's a real weakness of prompting: results are sensitive to small choices.
The top two designs are a statistical tie, so I don't over-claim the value of the definitions. And the test score lands close to validation, so choosing among eight designs didn't overfit.

[~45 s · 4:05–4:50]
Now, back to that question. In Experiment 2, my few-shot model agrees much more with Claude's text-based labels than with the star ratings, and Claude disagrees with the stars in the same way. Two different models, reading only the text, reach the same conclusion: a three-star rating often hides a negative review.
The takeaway is that star ratings are a noisy proxy for sentiment, so part of what looks like model error is really label noise. One honest caveat: agreement between two language models is not ground truth. But it suggests our test scores may understate what these models can do.

[~30 s]
My method fine-tunes bert-base-uncased for three-class sentiment classification. I tokenize each review and cap the input at 384 tokens; only 0.18 percent of reviews are longer than that. The model trains for three epochs on the same 40,000-review split used by the team, and I select the checkpoint with the best validation macro-F1. On an NVIDIA L4, the full training run took about 16.9 minutes.

[~35 s]
BERT produces three logits from the CLS representation. Hugging Face Trainer applies the standard unweighted cross-entropy loss. I did not add class weights because the training split is balanced across Negative, Neutral, and Positive. AdamW uses a learning rate of 2e-5, weight decay of 0.01, and 750 warmup steps. I evaluate and save at the end of every epoch, then reload the checkpoint with the highest validation macro-F1. The notebook can also resume from the last checkpoint if Colab disconnects.

SPEAKER: JN. ~60 s.
Same Llama 3.1 8B and exactly the same zero-shot prompt as Dinh's baseline, so the only difference is the fine-tuning. The base model is loaded in 4-bit and frozen; small low-rank adapter matrices are added to the attention and MLP projections and only those are trained: 42 million of 8 billion weights. The target is just the label, so the loss is computed on the label only. One epoch over the 40,000 training reviews took 114 minutes on one A100.

SPEAKER: JN. ~45 s, then leave this slide up for Q&A.
Three takeaways. One: fine-tuning half a percent of Llama's weights gives the best result, 0.84 macro-F1, against 0.78 for both fine-tuned BERT and the best prompt. Two: Neutral is the hardest class for every method, and it is mostly confused with Negative. Three: the label source matters; star labels are noisy for 3-star reviews, and each model agrees most with the labels it resembles. For a seller, BERT is the cheap option: the same macro-F1 as the best prompt at a fraction of the cost per review.
