[~50 s · 0:00–0:50]
Hello everyone, my name is Quoc, and our project is called ReviewLens. So, here is the problem. Online sellers get thousands of reviews, and it is hard to find the unhappy customers by reading them one by one. That's why we want a model that puts each review into one of three groups: Negative, Neutral or Positive.
In our team, we solve this same task in three different ways, with the same data. Longqi fine-tunes BERT, and Bhone fine-tunes Llama. My part is different, because I use Llama without any training. I only change the prompt.
For the main score, we use macro-F1, so Neutral is just as important as the other two classes. And please remember this example. It has three stars, but it sounds like a complaint. I will come back to it later.

[~60 s · 0:50–1:50]
Now, the data. All three of us use the same data, so if our results are different, it is because of the method. We start from about 20 million Amazon reviews for cell phones. Then we keep the reviews that are long enough to show an opinion, and we clean up the text.
For the labels, we use the star rating. But Neutral reviews are much less common than the others, so a model could almost skip Neutral and still get a good score. That's why we take a balanced sample of 50,000 reviews, and everyone uses the same train, validation and test split.
But I also had a question: is the star rating always correct? So I ran Experiment 2. I asked Claude to label new reviews by reading only the text, without the stars. Then we test every method on both kinds of labels, so we can see if a mistake comes from the model or from the label.

[~40 s · 1:50–2:30]
Next is my method, and the idea is simple: no training. I give Llama one prompt with the instructions, a short meaning of each label, a few example reviews, and then the new review. The model answers, and I take the label from its answer. I also use greedy decoding, so I get the same result every time.
So the main work is finding a good prompt. I tried eight prompts on the validation set, and I kept the test set for the very end. But one thing to note: the best prompt is about ten times longer, so each prediction is slower and costs more.

[~50 s · 2:30–3:20]
And here is the result. With a better prompt, macro-F1 goes from 0.68 to 0.78, without any training. But the interesting part is where the gain comes from. Negative and Positive were already easy, so almost all of the gain is in Neutral. I think the examples show the model what a "middle" review looks like.
However, Neutral is still the hardest class. In the confusion matrix, almost 30% of Neutral reviews are still predicted as Negative, but very few as Positive. And when I read these reviews myself, many of them really are complaints, even with three stars. So the question is: is the model wrong, or is the label wrong?

[~35 s · 3:20–3:55]
Before I answer that, here is how I picked the prompt. I learned two things. First, examples help more than definitions. Second, more examples are not always better. With more than five examples per class, the score went down. And using different examples can also change the score, so prompting is quite sensitive.
Also, the test score is close to the validation score, so I don't think we overfit when we picked the prompt.

So, back to my question. In Experiment 2, my model gets 0.88 against Claude's labels, but only 0.79 against the stars, on the same reviews. And Claude also disagrees with the stars in the same way. My method fine-tunes bert-base-uncased for three-class sentiment classification. I tokenize each review and cap the input at 384 tokens; only 0.18 percent of reviews are longer than that. The model trains for three epochs on the same 40,000-review split used by the team, and I select the checkpoint with the best validation macro-F1. On an NVIDIA L4, the full training run took about 16.9 minutes.

[~35 s]
BERT produces three logits from the CLS representation. Hugging Face Trainer applies the standard unweighted cross-entropy loss. I did not add class weights because the training split is balanced across Negative, Neutral, and Positive. AdamW uses a learning rate of 2e-5, weight decay of 0.01, and 750 warmup steps. I evaluate and save at the end of every epoch, then reload the checkpoint with the highest validation macro-F1. The notebook can also resume from the last checkpoint if Colab disconnects.

SPEAKER: JN. ~45 s, then leave this slide up for Q&A.
Three takeaways. One: fine-tuning half a percent of Llama's weights gives the best result, 0.84 macro-F1, against 0.78 for both fine-tuned BERT and the best prompt. Two: Neutral is the hardest class for every method, and it is mostly confused with Negative. Three: the label source matters; star labels are noisy for 3-star reviews, and each model agrees most with the labels it resembles. For a seller, BERT is the cheap option: the same macro-F1 as the best prompt at a fraction of the cost per review.
